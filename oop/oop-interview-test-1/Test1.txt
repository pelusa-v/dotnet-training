Inheritance, Polymorphism, Encapsulation, Abstraction.
Inheritance: The ability of an object to inherit properties and behavior from a parent class and make these as own.
- Example: The classes Cat and Tiger inherit from the class Feline, they inherit properties like "numberOfPaws" or methods like lurk.

Polymorphism: The ability of different objects to be treated as a general object, but having their own behavior and properties when you inspect their details (and they can have methods or properties with the same name, but different meaning depending of the object)
- Example: The abstract class BarkAnimal, define an abstract method called Bark, there are two classes called Dog and Seal, the each of them implement the Bark method to emit a specific sound, so in other client class, I can define a List of BarkAnimal, and add a Dog and a Seal, and put them into a for loop to execute the Bark method. In this case, the client class doesn't know about the details of Bark method, and treats Dog and Seal as BarkAnimal, so Dog and Seal are applying polymorphism

Encapsulation: The ability to group data and behavior into a class, keeping apart from other classes and having access level to this elements (properties, methods, etc)
Example: The class Car has the method "Run" as public, and has a method "StartEngine" as private, I can use the Run method only after defining a Car Object. If I create a static class with methods, I need to call the class before to use the methods.

Abstraction: The ability to not depending on the details of an object, just in the behaviors
Example: I have a class PetShelter that has a method "PutToSleep" that receives a pet and execute, and I have other classes Dog, Cat, Turtle, Bird that hav a lot of properties and methods, but I'm interested in the Sleep method of them, so I can use an interface IPet that define a method Sleep, so Dog, Cat, Turtle and Bird implement this method. Now the PutToSleep method receive a IPet object, I'm saying that I will receive objects who have a Sleep method, depending only of the behavior of IPet and avoid depending on details

2- Abstraction focus in representing a group of classes based on the behavior using interfaces of abstract classes meanwhile encapsulation focus in make properties and methods part of a class, giving the ability to be inherited from subclasses. Abstraction uses encapsulation

5- Yes, I can. Dependency inversion: classes shouldn't depend on implementations (classes), should depend on abstractions (interfaces or abstract classes), so based on this, if I have a class A that requires an object of class B in the constructor, applying dependency inversion, I create an abstraction called IB, and receive the IB in the constructor of A, so now A and B are depending on IB.
Without dependency inversion:  A-->B (dependency flows from A to B)
with dependency inversion:  A-->IB<--B (dependency flows from A to IB and B to IB, inverted dependency)

public abstract class Shape
{
    public abstract double Area();
}

public class Circle : Shape
{
    public double Radius { get; set; }
    public override double Area()
    {
        return Math.PI * Radius * Radius;
    }
}

public class Triangle : Shape
{
    public double Base { get; set; }
    public double Height { get; set; }
    public override double Area()
    {
        return 0.5 * Base * Height;
    }
}

public class Rectangle : Shape
{
    public double Width { get; set; }
    public double Height { get; set; }
    public override double Area()
    {
        return Width * Height;
    }
}

public class Singleton
{
    private static Singleton _instance;
    private static readonly object _lock = new object();

    private Singleton()
    {
    }

    public static Singleton Instance
    {
        get
        {
            if (_instance == null)
            {
                lock (_lock)
                {
                    if (_instance == null)
                    {
                        _instance = new Singleton();
                    }
                }
            }

            return _instance;
        }
    }
}
